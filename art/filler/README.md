# web/art/filler — generated art, parked

A library of generated bar-girl art kept for later use. **Nothing in the game
loads this directory** — `tests/js/art.test.js` asserts that it stays that way,
because these filenames are guarded by no naming rule. When a frame finds a
real use, move it to a directory that does guard its names:

| home | rule |
|---|---|
| `web/art/rooms/` | filename must match a `ROOMS` id |
| `web/art/regions/` | filename must match a live region slug |
| `web/portraits/pics/` | every file needs a referencing `selfies`/`paidPics` entry in world.js |

Format and budget still apply here: PNG, **≤ 400 KB each** (they're in git like
everything else).

Generated by `../portrait_gen`'s `characters.py` `FILLER_PICS` / `POSE_PICS`.
Content sits in the same tier the game already ships in the phone gallery —
suggestive, fully clothed, adults, with a leading nudity guard on the negative
(`_POOL_GUARD`). `docs/spicy-content-gating.md` is the boundary: the tasteful
tier is generated, the explicit tier stays author-supplied.

Two things learned the hard way, worth keeping in mind before generating more:

- **No cues, or anything long and thin held in two hands.** Every anatomy defect
  in the first passes — broken cues, a third arm, an extra hand — came from a
  pool cue. Without one, renders come back clean.
- **This model won't put a torso horizontal.** Bent-over-the-table and squatting
  poses were both refused across ~15 renders; prompt wording moved it slightly,
  negatives barely at all. It gives reliable rear/three-quarter views of a woman
  *leaning* on something, so the set is built on leaning. Real pose control would
  need an OpenPose ControlNet, which the pipeline doesn't have (only tile).
